## 3. How to measure (keep the load off the local machine)

- **CI A/B workflow** `.github/workflows/bench-ab.yml` (on the PR branch): push any branch named `exp/<name>` carrying `.github/bench-ab.json`, e.g. `{"refs": ["kasper/laughing-hamilton-16fyge", "HEAD"], "tests": "tests/vitest-user-event/", "reps": 3, "copies": [1, 2], "profile": "timings"}` (`HEAD` = the pushed commit; `tests` may be one file or `-c vitest.bench.config.ts`; `fast` "1"/"0"; `build` production/development; `profile` none/timings/profile). Each copy checks out and builds every ref, warms each up, runs them interleaved on ONE runner, prints `results.tsv` in the job log and the medians + ratio to the first ref in the step summary; artifacts `bench-ab-<copy>` hold logs and timings/profiles. Read results from the "Run the rounds" step log (`round ref duration_s files_ms tests` lines) when the summary is inconvenient. `workflow_dispatch` exists but only works once the file is on main (GitHub rule); Kasper does not want a PR to main for it; the exp/ push is the trigger.
- **Benchmark workflow** `.github/workflows/vitest-vs-playwright.yml`: on PR; fast + default on one runner with the ratio table; a `primitives` job (both modes); a `profile` job (CPU profile + trace of the page).
- **Local** (only short runs): `cd playground/vitest-vs-playwright-notes && VITEST_PLUGIN_RSC_FAST=1 pnpm exec vitest run --maxWorkers 1 tests/vitest-user-event/notes-list.test.tsx` (after `pnpm --filter vitest-plugin-rsc build`); `-c vitest.profile.config.ts` with `VITEST_PROFILE=timings|trace` and `python3 test/timings-summary.py` / `test/profile-summary.py` / `test/trace-summary.py`; the primitives: `BENCH_SHELL_START=$(date +%s%3N) pnpm exec vitest run -c vitest.bench.config.ts --maxWorkers 1` then `python3 bench/compare.py a.json b.json`. After `wip/mode-api` lands the env var is `VITEST_PLUGIN_RSC_MODE=fast`.
- **Noise.** CI runner-to-runner: 22–37 s for the same 500 tests; within one runner interleaved: ±2–3%. Local: ±5–10%. `pnpm exec` costs ~1.1 s per invocation (use `./node_modules/.bin/vitest` or `bun vitest`). Switching Node↔Bun or fast↔default re-optimizes deps (6–7 s) until the cacheDir fixes land (SB-2410, SB-2418/impl-2).
- **pnpm 11 gotcha.** A new `patchedDependencies` entry is ignored by the optimistic repeat-install: `pnpm install --config.optimistic-repeat-install=false` once.
